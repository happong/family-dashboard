# 우리집 다이어리 (family-dashboard)

가족 계모임 · 여행 계획 · 가족회의를 관리하는 개인용 대시보드 뼈대입니다.
현재는 **화면 구조 + Google 로그인 인증**만 구현되어 있고, 각 모듈(계모임/여행/회의)의
실제 데이터 기능은 다음 단계에서 채웁니다.

## 파일 구조

```
family-dashboard/
├── index.html   # 화면 골격 (로그인 화면 + 5개 탭)
├── style.css    # 화이트/베이지 톤 디자인
├── config.js    # Firebase 설정값 + 접근 허용 이메일 목록 (직접 채워야 함)
├── auth.js      # Google 로그인 + 이메일 화이트리스트 체크
├── app.js       # 탭 전환 라우팅
├── modules/
│   ├── finance.js   # 계모임
│   ├── travel.js    # 여행 (사전계획/실제일정/맛집/별점/사진)
│   ├── meeting.js   # 가족회의
│   └── alerts.js    # 알림
├── backend/
│   └── Code.gs      # Apps Script 백엔드 (GitHub엔 참고용으로만 두면 됨)
└── README.md
```

## 스프레드시트에 필요한 시트 탭 전체 목록 (한눈에 보기)

한 스프레드시트 안에 아래 11개 탭을 만들어야 전체 기능이 동작해요.
각 모듈 셋업 섹션에도 같은 내용이 나눠서 설명돼 있어요.

| 탭 이름 | 헤더(1행) |
|---|---|
| 거래내역 | 날짜 \| 구분 \| 항목 \| 금액 \| 등록자 \| 메모 |
| 여행 | 여행ID \| 여행지 \| 시작일 \| 종료일 \| 상태 \| 메모 |
| 일정 | 여행ID \| 구분 \| 날짜 \| 시간 \| 장소 \| 메모 |
| 맛집 | 여행ID \| 상점명 \| 메뉴 \| 별점 \| 등록자 \| 재방문의사 \| 메모 |
| 여행평점 | 여행ID \| 등록자 \| 별점 \| 메모 |
| 사진 | 여행ID \| URL \| 설명 \| 유형 |
| 회의이슈 | 이슈ID \| 제목 \| 설명 \| 등록일 |
| 회의진행도 | 이슈ID \| 날짜 \| 진행도 \| 메모 |
| 회의논의 | 이슈ID \| 날짜 \| 논의내용 \| 다음아젠다 |
| 회의할일 | 할일ID \| 이슈ID \| 담당자 \| 내용 \| 마감일 \| 등록일 |
| 회의할일완료 | 할일ID \| 완료일 |

## 계모임 모듈 셋업

1. https://console.firebase.google.com 에서 새 프로젝트 생성
2. 왼쪽 메뉴 Authentication → 로그인 방법 → **Google** 활성화
3. 프로젝트 설정(⚙️) → 일반 → "내 앱"에서 웹 앱 추가 → `firebaseConfig` 값 복사
4. `config.js`의 `firebaseConfig`에 붙여넣기
5. `config.js`의 `ALLOWED_EMAILS`에 접속을 허용할 가족 구성원 Gmail 주소 입력
6. Firebase Console → Authentication → 설정 → **승인된 도메인**에 GitHub Pages 주소
   (예: `yourname.github.io`) 추가 — 이거 안 하면 로그인 팝업이 막힙니다.

## GitHub Pages 배포

```
git init
git add .
git commit -m "family dashboard skeleton"
git remote add origin <레포 주소>
git push -u origin main
```
그 다음 레포 Settings → Pages → Branch를 `main`으로 지정하면 배포됩니다.

## ⚠️ 보안 관련 주의 (정확히 알아두어야 할 부분)

- `ALLOWED_EMAILS` 체크는 **브라우저(클라이언트) 안에서** 실행됩니다.
  즉, 개발자도구로 코드를 보면 이 목록 자체는 누구나 읽을 수 있고,
  로그인 성공 후 이 체크를 우회하는 것도 기술적으로는 가능합니다.
- 가족끼리 쓰는 용도로는 이 정도로 충분하지만, **계좌번호·주민번호 같은
  진짜 민감한 정보를 저장할 계획이라면 이 방식만으로는 부족**합니다.
  그 경우엔 데이터 저장소(Firestore 등)의 보안 규칙에서도 같은
  이메일 화이트리스트를 검사하도록 서버 쪽 규칙을 추가해야 합니다.
- `firebaseConfig`의 `apiKey`는 비밀키가 아니라 프로젝트 식별용 공개 값이라
  GitHub 공개 레포에 올려도 괜찮습니다 (Google 공식 안내 기준).

## 계모임 모듈 셋업

1. Google Sheets에서 새 스프레드시트를 만들고 시트 이름을 `거래내역`으로 변경
2. 1행에 헤더를 순서대로 입력: `날짜 | 구분 | 항목 | 금액 | 등록자 | 메모`
3. 확장 프로그램 → Apps Script → `backend/Code.gs` 내용을 그대로 붙여넣기
4. 배포 → 새 배포 → 웹 앱으로 배포 (실행 계정: 나 / 액세스: 전체 허용)
5. 배포된 웹 앱 URL을 `modules/finance.js` 맨 위 `FINANCE_API_URL`에 붙여넣기

기여도는 **각자의 누적 수입 ÷ 전체 수입 총합 × 100**으로 계산했어요.
다른 기준(예: 지출도 포함해서 계산)으로 바꾸고 싶으면 `modules/finance.js`의
`renderContribution()` 함수만 고치면 됩니다.

## 여행 모듈 셋업 (1단계: 사전계획 + 실제일정)

같은 스프레드시트에 시트 탭 2개를 추가하세요.

- `여행` 탭 헤더: `여행ID | 여행지 | 시작일 | 종료일 | 상태 | 메모`
- `일정` 탭 헤더: `여행ID | 구분 | 날짜 | 시간 | 장소 | 메모`
  (구분 값은 `사전계획` 또는 `실제일정`으로 입력됩니다)

## 여행 모듈 2단계 (맛집 평점 · 여행지 별점 · 사진)

시트 탭 3개를 추가로 만드세요.

- `맛집` 탭 헤더: `여행ID | 상점명 | 메뉴 | 별점 | 등록자 | 재방문의사 | 메모`
  (재방문의사 값은 `예` 또는 `아니오`)
- `여행평점` 탭 헤더: `여행ID | 등록자 | 별점 | 메모`
- `사진` 탭 헤더: `여행ID | URL | 설명 | 유형`
  (유형 값은 `사진` 또는 `동영상`. 파일 자체가 아니라 Google Drive 공유
  링크를 저장하는 방식이에요 — Drive에서 "링크가 있는 모든 사용자"로
  공유 설정을 해둬야 가족이 클릭했을 때 열립니다.)

맛집은 같은 상점명으로 여러 명이 각각 등록하면 자동으로 평균 별점과
재방문 의사 비율(예: 3/4명)로 합산해서 보여줘요.

## 가족회의 모듈 셋업

시트 탭 5개를 추가하세요.

- `회의이슈` 탭 헤더: `이슈ID | 제목 | 설명 | 등록일`
- `회의진행도` 탭 헤더: `이슈ID | 날짜 | 진행도 | 메모`
  (진행도는 0~100 숫자를 새로 기록하는 방식이에요. 수정이 아니라
  누적 기록이라, 가장 최근 날짜의 값이 "현재 진행도"로 표시됩니다.)
- `회의논의` 탭 헤더: `이슈ID | 날짜 | 논의내용 | 다음아젠다`
- `회의할일` 탭 헤더: `할일ID | 이슈ID | 담당자 | 내용 | 마감일 | 등록일`
- `회의할일완료` 탭 헤더: `할일ID | 완료일`
  (할 일을 "완료 처리"하면 이 탭에 기록이 추가돼요. 되돌리기 기능은
  아직 없어요 — 잘못 눌렀다면 시트에서 해당 행을 직접 지우면 됩니다.)

기여도는 **전체 이슈를 통틀어 완료한 할 일 개수 기준**으로 계산했어요.
특정 이슈 하나만의 기여도를 보고 싶으시면 말씀해주세요, 계산 범위를
좁히는 건 어렵지 않아요.

## 알림 모듈 — 알아두어야 할 한계

브라우저 알림은 **이 사이트 탭을 열어두고 있을 때만** 작동해요. 앱을
꺼두거나 컴퓨터를 끄면 알림이 오지 않습니다. 이건 기술적 한계이지
버그가 아니에요.

더 확실한 알림이 필요하면 `backend/Code.gs`에 포함된 `sendDailyDigest()`
함수를 Apps Script의 시간 기반 트리거로 등록하세요. 그러면 매일 정해진
시간에 미완료 할 일 목록을 가족 이메일로 보내줍니다.

1. `sendDailyDigest()` 함수 안의 `familyEmails` 배열을 실제 가족
   이메일 주소로 바꾸기
2. Apps Script 편집기 왼쪽 시계 모양 아이콘(트리거) 클릭
3. 트리거 추가 → 실행할 함수: `sendDailyDigest` → 이벤트 소스:
   시간 기반 → 매일 타이머 → 원하는 시간대 선택 → 저장

## 백엔드 업데이트 시 공통 주의사항

`backend/Code.gs`를 바꿀 때마다 Apps Script 편집기에서 코드를 교체한
뒤, **배포 → 배포 관리 → 편집(연필 아이콘) → 새 버전으로 배포**를
해야 반영됩니다. "새 배포"를 새로 만들면 URL이 바뀌어서
`modules/finance.js`의 `FINANCE_API_URL`도 같이 바꿔야 하니 주의하세요.
